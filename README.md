# METOPON（仮）

ブラウザで気軽に遊べる、マウス／タッチ操作だけの思考型パズルゲームです。

このREADMEは完成済みの仕様書ではなく、相談しながら内容を固めていくための企画書です。  
まず小さく遊べる試作を作り、面白さを確認しながらルールや演出を追加していきます。

## 1. 企画概要

| 項目 | 内容 |
| --- | --- |
| 仮タイトル | METOPON（メトポン） |
| ジャンル | 短時間で遊べる思考型パズル |
| 対応環境 | PC／スマートフォンのWebブラウザ |
| 操作 | マウスまたはタッチのみ |
| 1問の時間 | 30秒〜3分程度 |
| 対象 | 複雑な操作は苦手だが、少し考えて解く気持ちよさを楽しみたい人 |
| 特徴 | シンプルなルール、短い問題、AIを利用した問題生成 |

## 2. 目指す遊び

- 説明を長く読まなくても、触ればルールが分かる
- 操作の難しさではなく「気づき」で解ける
- 正解した瞬間に、音・動き・手応えが気持ちいい
- 失敗しても、すぐにやり直せる
- 1問だけでも遊べるが、つい次の問題にも進みたくなる
- AIが問題候補を作ることで、新しい問題を増やしやすい

難解なロジックパズルを長時間考えるゲームではなく、  
「少し考える → 試す → 動きを見る → 分かった！」を短い周期で繰り返すゲームを目指します。

## 3. ゲームの基本案

### 仮ルール：動きを組み立てるワンアクション・パズル

小さな盤面に、スタート地点、ゴール、障害物、方向を変える部品などが配置されています。  
プレイヤーは盤面上の部品をクリックして状態を切り替え、準備ができたらスタートボタンを押します。

スタートするとキャラクターやエネルギーが自動で移動します。  
障害物を避け、必要なものをすべて回収してゴールに到達すればクリアです。

### 基本の流れ

1. 盤面を見る
2. 部品をクリックして向きや状態を変える
3. スタートボタンを押す
4. 自動で動く様子を見る
5. 失敗したら配置を直して再挑戦する
6. 条件を満たしてゴールすればクリア

### 操作

- クリック／タップ：部品の向きや状態を変更
- ドラッグ：採用する場合のみ、部品の移動に使用
- スタート：仕掛けを実行
- リセット：実行前の状態に戻す
- ひとつ戻す：直前の操作を取り消す

最初の試作では、クリックとスタートだけで遊べる形を優先します。

## 4. 盤面に登場する要素

### 最初から使うもの

| 要素 | 役割 |
| --- | --- |
| スタート | 移動物が出現する場所 |
| ゴール | 最終目的地 |
| 壁 | 通過できない障害物 |
| 方向パネル | 移動方向を90度変える |
| スイッチ | 扉などの状態を切り替える |
| 回収物 | ゴール前にすべて取る必要があるもの |

### 後から追加する候補

- 一度だけ使える方向パネル
- 色の付いた鍵と扉
- ワープ
- 分岐
- 押せる箱
- 一定周期で切り替わる床
- 複数の移動物
- 同時に条件を満たす仕掛け
- 移動回数や操作回数の制限

要素を一度に増やさず、ひとつずつ追加して問題の変化を確認します。

## 5. クリア条件と評価

基本のクリア条件は次のとおりです。

- 必要な回収物をすべて取得する
- 移動物がゴールに到達する
- 禁止された場所に入らない

クリア時の評価候補：

- クリアのみ：誰でも次へ進める
- 少ない操作回数でクリア：星を追加
- 想定解と同じ最短手数：最高評価

最短手数を強制せず、まず解けたことを肯定する設計にします。

## 6. AIによる問題生成

AIに完成した問題をそのまま公開させるのではなく、候補データを作らせたあと、プログラムで検証します。

### 生成の流れ

1. AIが盤面データと想定解を作る
2. ソルバーが実際に解けるか検証する
3. 最短手数と解答数を調べる
4. 難易度を推定する
5. 条件を満たした問題だけを採用する
6. 必要なら人間が遊んで最終確認する

### 自動チェックする項目

- 必ず解ける
- 初期状態ですでにクリアしていない
- ループして終了不能にならない
- 指定した手数の範囲に収まる
- 偶然クリックするだけで解ける問題を減らす
- 同じ形の問題が大量に重複しない
- 可能なら解答を1つに絞る

AIは「問題の案を出す役」、ソルバーは「正しさを保証する役」とします。

## 7. 難易度

| 難易度 | 内容 |
| --- | --- |
| やさしい | 1〜2回の操作。新しい仕掛けを覚える |
| ふつう | 3〜5回の操作。複数の仕掛けを組み合わせる |
| むずかしい | 先の動きを予測しないと解けない |
| チャレンジ | 最短手数、複数ルート、特殊条件を含む |

難しさは盤面の大きさだけでなく、必要な読みの深さや紛らわしい選択肢の数で調整します。

## 8. ゲームモード案

### ステージモード

用意された問題を順番に遊びます。  
最初はチュートリアルを兼ねて、新しい仕掛けを少しずつ追加します。

### 今日の問題

毎日1問を提供します。  
同じ問題を全員が遊べるため、結果を共有しやすくなります。

### ランダム問題

難易度を選び、自動生成された問題を続けて遊びます。

### エディットモード

プレイヤーが問題を作り、URLや短いコードで共有します。  
MVP完成後の追加候補です。

## 10. 見た目と演出

- 小さく見ても判別しやすい、単純な形を使う
- 色だけに頼らず、形や模様でも区別できるようにする
- 成功時は短く気持ちのよいアニメーションと効果音を入れる
- 失敗時に強く責める表現は使わない
- 自動実行中の動きは、原因と結果が追える速さにする
- 必要なら倍速と一時停止を追加する

## 11. 技術案

最初はインストール不要のWebゲームとして作ります。

### 第一候補

- TypeScript
- HTML / CSS
- Canvas または SVG
- Vite
- ステージデータはJSON
- GitHub Pagesで公開

盤面がマス目中心で部品数も少ない間は、SVGが扱いやすい候補です。  
表示物が増えたり演出が複雑になった場合はCanvasを検討します。

### 基本方針

ゲームの判定ロジックと表示を分離します。

- ゲームロジック：盤面、移動、当たり判定、クリア判定
- 表示：盤面や部品の描画、アニメーション
- 入力：マウス／タッチ操作
- 問題データ：JSON
- ソルバー：問題の検証と最短解の探索

この分離により、同じロジックをゲーム本体と問題検証の両方で利用できます。

## 12. ステージデータ案

```json
{
  "id": "stage-001",
  "width": 5,
  "height": 5,
  "start": { "x": 0, "y": 2, "direction": "right" },
  "goal": { "x": 4, "y": 2 },
  "walls": [
    { "x": 2, "y": 2 }
  ],
  "parts": [
    { "x": 1, "y": 2, "type": "turn", "state": "down" },
    { "x": 1, "y": 3, "type": "turn", "state": "right" }
  ],
  "items": [
    { "x": 3, "y": 3, "type": "collect" }
  ],
  "par": 2
}
```

実装を始める際に、実際のルールに合わせて形式を確定します。

## 13. MVP（最初に作る範囲）

最初の目標は、面白さを確認できる最小版です。

- 5×5程度の盤面
- スタートとゴール
- 壁
- クリックで向きが変わる方向パネル
- 自動移動
- クリア／失敗判定
- リセット
- 手作り問題を5問
- PCとスマートフォンのブラウザ対応
- 効果音は最低限
- セーブはブラウザ内のみ

AI生成、ログイン、ランキング、エディット機能はMVPには入れません。  
まず手作り問題で、基本ルールそのものが面白いか確認します。

## 14. 開発手順

1. 盤面と移動ルールだけの試作を作る
2. 手作り問題を5問用意する
3. 実際に遊んで、操作とテンポを調整する
4. 基本ルールを確定する
5. ソルバーを作る
6. 問題の自動生成を試す
7. 演出、サウンド、ステージ選択を追加する
8. GitHub Pagesで公開する

## 15. 今後相談して決めたいこと

この企画で特に先に決めたいのは次の点です。

1. 動くものは「キャラクター」「ボール」「光」のどれがよいか
2. 部品は向きを変えるだけか、盤面上を移動できるようにするか
3. 実行中に追加操作できるゲームにするか、実行前だけ操作するか
4. パズル寄りにするか、リズムやタイミング要素も入れるか
5. かわいい雰囲気、機械的な雰囲気、抽象的な雰囲気のどれにするか
6. 1問ごとの最短手数を評価するか
7. AI生成問題を毎日配信するか、開発時の問題作成支援だけに使うか

## 16. 現在の決定事項

- ブラウザで遊べる
- マウス／タッチだけで操作できる
- 短時間で1問を遊べる
- 考える楽しさはあるが、面倒すぎない
- 問題を増やす仕組みにAIを利用する
- AIが作った問題はプログラムで検証する
- 最初は小さな試作から始める
