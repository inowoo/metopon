# METOPON（メトポン／仮）

**「入れ替えて、そろえて、打ち上げる」連鎖アクションパズル。**

『メテオス』の打ち上げと再加速の気持ちよさ、『パネルでポン』の横入れ替えとせり上がる盤面を参考にしつつ、ブラウザでマウス／タッチだけで遊べる独自ルールを目指します。

> このREADMEは、相談しながら更新していく企画・仕様書です。  
> 最初から大作にはせず、コアルールを遊べる試作を作って面白さを検証します。

## 1. 企画概要

| 項目 | 内容 |
| --- | --- |
| 仮タイトル | METOPON（メトポン） |
| ジャンル | 打ち上げ連鎖アクションパズル |
| 対応環境 | PC／スマートフォンのWebブラウザ |
| 操作 | マウスまたはタッチ |
| プレイ時間 | パズル：1問1〜5分／エンドレス：任意 |
| 基本人数 | 1人 |
| 中心となる遊び | 横交換、3マッチ、打ち上げ、空中再連鎖 |
| 開発方針 | まず1人用の小さな試作を作り、対戦やAI生成は後から検討 |

## 2. ゲームの一言説明

下からせり上がるブロックを横に入れ替え、同じ種類を縦か横に3個以上そろえます。

そろったブロックはただ消えるのではなく、**その上に載っているブロックの塊を上空へ打ち上げます**。  
打ち上がった塊が落ちてくる前に、さらにマッチを作ると再加速します。

連鎖を重ねてブロックを画面上端の外へ飛ばし、盤面があふれないようにするゲームです。

## 3. このゲームの面白さ

- 横交換だけなので、触った瞬間に操作が分かる
- 3個そろえる場所によって、打ち上がる量が変わる
- 「今すぐ消す」か「大きな塊を作ってから飛ばす」かを考えられる
- 空中の短い時間に次のマッチを作る、忙しすぎないアクション性がある
- 大量のブロックが一気に飛び出す爽快感がある
- 連鎖を仕込めたときに、偶然ではなく自分で解いた手応えがある

## 4. 基本ルール

### 4.1 盤面

- 盤面は仮に**横6マス × 縦12マス**
- ブロックは5種類から開始
- 盤面の下から、一定時間ごとに新しい1段がせり上がる
- 上端の危険ラインにブロックが達したまま一定時間経過するとゲームオーバー

盤面サイズ、色数、せり上がり速度は試作後に調整します。

### 4.2 操作

- ブロックをクリック／タップして選択
- 左右どちらかの隣接ブロックを選ぶと横交換
- または、ブロックを左右へ短くスワイプして交換
- 空きマスとの交換も可能
- 縦方向の交換はできない

PCではドラッグ、クリック2回の両方に対応し、スマートフォンではスワイプとタップに対応する想定です。

### 4.3 マッチ

- 同じ種類のブロックを**縦または横に3個以上**そろえると点火
- 4個以上、十字、L字、同時消しは強い打ち上げになる
- マッチしたブロックは短い点火演出のあと消える
- 空いた場所では、支えを失ったブロックが下へ落ちる
- 落下後に自然にそろった場合も連鎖になる

### 4.4 打ち上げ

マッチしたブロックは「ロケットの噴射台」の役割を持ちます。

1. マッチが成立する
2. マッチした場所が点火する
3. その上に載っている、上下左右につながったブロック群が打ち上がる
4. 打ち上がったブロックが上端を越えると盤面から除去される
5. 上端まで届かなかったブロックは、少し滞空したあと落下する

1回のマッチで必ず全てを消せるわけではありません。  
小さなマッチでは少ししか上がらず、大きな塊は重いため高く飛びにくくします。

### 4.5 推力の仮仕様

最初の試作では、分かりやすさを優先して次のようにします。

| マッチ | 基本推力 |
| --- | ---: |
| 3個 | 2マス上昇 |
| 4個 | 4マス上昇 |
| 5個以上 | 6マス上昇 |
| 十字／L字 | 追加で2マス上昇 |
| 同時に複数ライン | ライン数に応じて加算 |

打ち上げる塊が大きいほど推力を少し減らす案も検討します。  
ただし計算が直感的でなくなる場合は、重さの概念を入れずに演出だけで表現します。

### 4.6 空中再点火

打ち上げられたブロックは、約1秒間の「空中状態」になります。

- 空中状態でも横交換できる
- 空中の塊で新しいマッチを作ると再点火
- 再点火すると落下が止まり、さらに上へ加速する
- 再点火を繰り返すほど連鎖数と得点が増える
- 地上へ戻る前に上端を越えれば、大量除去になる

これがMETOPONの中心となる遊びです。

## 5. 連鎖の種類

### 落下連鎖

マッチでブロックが消え、上のブロックが落下した結果、次のマッチが成立します。

### 空中連鎖

打ち上がった塊を操作し、空中にいる間に次のマッチを成立させます。

### 仕込み連鎖

あらかじめ複数のマッチ候補を作り、最初の交換をきっかけに順番に発火させます。

### 同時点火

複数の場所で同時にマッチを成立させ、大きな推力を発生させます。

空中連鎖をもっとも高得点にし、このゲームらしい遊びへ誘導します。

## 6. 盤面の進行

### 通常時

- ブロックの列がゆっくり下からせり上がる
- プレイヤーは自由に横交換できる
- 任意のボタンで一時的にせり上がりを早められる
- マッチ、落下、打ち上げの処理中は自然上昇を一時停止する

### 危険状態

- ブロックが危険ラインに入ると、せり上がりが止まる
- 警告音と表示で危険を知らせる
- 猶予時間内に高さを下げれば続行
- 猶予時間を超えるとゲームオーバー

操作中に突然終了せず、最後に立て直す機会を作ります。

## 7. 得点

基本得点は、次の要素から計算します。

- マッチしたブロック数
- 打ち上げて上端から除去したブロック数
- 連鎖数
- 空中連鎖
- 同時点火
- 一度に飛ばした塊の大きさ

仮の考え方：

```text
獲得点 = 基本点
       + 上端から飛ばしたブロック数 × 除去点
       + 連鎖倍率
       + 空中連鎖ボーナス
```

細かい式は、遊びやすさが固まってから決めます。  
試作段階では「大量に飛ばす」「空中でつなぐ」ほど高得点になることだけ明確にします。

## 8. ゲームモード

### 8.1 パズルモード

決められた盤面を、指定条件で解く思考型モードです。

条件の例：

- 3手以内に全ブロックを打ち上げる
- 1回の打ち上げで10個以上飛ばす
- 2連鎖を作る
- 指定されたブロックをすべて消す
- 盤面を危険ラインより下まで戻す

パズル中は時間と自動せり上がりを止められます。  
最初は落ち着いて考え、実行結果を見てすぐやり直せる形にします。

### 8.2 エンドレスモード

ブロックがあふれるまで遊び続ける基本のアクションモードです。

- 時間とともにせり上がり速度が増す
- 一定得点ごとにレベルアップ
- ハイスコアをブラウザに保存
- 短時間でも遊べるよう、序盤から適度に展開を作る

### 8.3 今日の問題（将来案）

毎日同じパズル問題を全員に提供します。  
結果は手数、得点、クリア時間で比較できます。

### 8.4 対戦モード（将来案）

連鎖や大量打ち上げによって、相手へ「重いブロック」を送ります。  
最初の完成範囲には含めません。

## 9. パズル問題の生成と検証

問題生成は、AIだけに正解を判断させません。  
AIや自動生成器が候補を作り、ゲームと同じルールを使うソルバーで検証します。

### 生成手順

1. 問題の目的と難易度を決める
2. 盤面候補を生成する
3. ソルバーで解けるか調べる
4. 最短手数と解答数を求める
5. 不要なブロックや偶然解ける手を検査する
6. 条件を満たす問題だけ採用する
7. 人間が遊んで面白さを最終確認する

### 自動検証する項目

- 初期状態ですでにマッチしていない
- 指定手数以内に解ける
- 想定外の簡単すぎる解法がない
- 操作不能や無限ループが起きない
- 同型の問題が重複しない
- 連鎖の結果が常に再現可能
- 運に依存せず解ける

AIは盤面のアイデアやテーマ作りに使い、正しさはソルバーで保証します。

## 10. ブロックの種類

MVPでは通常ブロック5種類だけを使います。

| 種類 | 見分け方 |
| --- | --- |
| 1 | 色＋丸 |
| 2 | 色＋三角 |
| 3 | 色＋四角 |
| 4 | 色＋星 |
| 5 | 色＋波線 |

色だけで区別せず、形や模様を必ず併用します。

追加候補：

- おじゃまブロック：隣接マッチの点火で通常ブロックに変わる
- 重量ブロック：打ち上げに強い推力が必要
- ワイルドブロック：隣接する種類として扱う
- 爆発ブロック：周囲を巻き込む
- 固定ブロック：一度点火させると交換可能になる

特殊ブロックは、基本ルールだけで面白いことを確認してから追加します。

## 11. 処理順

ゲームの結果が予測できるよう、処理順を固定します。

1. プレイヤーが横交換する
2. 全マッチを同時に判定する
3. マッチしたブロックを点火する
4. 対象となる塊と推力を確定する
5. 打ち上げる
6. 上端を越えたブロックを除去する
7. 残った空中ブロックの操作時間を開始する
8. 再点火があれば、連鎖数を増やして再び打ち上げる
9. 再点火がなければ落下する
10. 落下後のマッチを判定する
11. 盤面が安定したら、せり上がりを再開する

演出中と内部判定のタイミングがずれないよう、ゲームロジック側は固定ステップで処理します。

## 12. 操作感

- 入れ替えは入力直後に反応する
- マッチしない交換も成立させる
- 連続入力を受け付け、演出待ちを減らす
- どの塊が打ち上がるか、点火前に一瞬ハイライトする
- 空中操作の残り時間を、枠の光や音で分かりやすくする
- 誤操作に備え、パズルモードには「一手戻す」を用意する
- スマートフォンでは縦持ちを基本にする

## 13. 見た目と音

### ビジュアル方針

- 明るい宇宙工場、または抽象的な発射装置を仮テーマにする
- ブロックは小さい画面でも区別できる単純な形にする
- 色覚特性にかかわらず遊べるよう、色・形・模様を併用する
- 危険状態は赤色だけでなく、枠の点滅と形の変化でも伝える
- 打ち上げ方向と対象の塊を線や光で予告する

### サウンド方針

- 交換、点火、浮上、再点火、画面外への射出を別の音にする
- 連鎖ごとに音程と厚みが上がる
- 大量打ち上げでは短い決め音を鳴らす
- 音を消しても、視覚情報だけで遊べるようにする

## 14. 技術案

- TypeScript
- HTML / CSS
- Canvas 2D
- Vite
- ステージデータはJSON
- Vitestでゲームロジックをテスト
- GitHub Pagesで公開

ブロックの移動、落下、打ち上げ、連鎖演出が多いため、描画はCanvas 2Dを第一候補にします。

### 構成方針

ゲームルールと表示を分離します。

```text
GameState
├─ Board             盤面データ
├─ SwapSystem        横交換
├─ MatchSystem       マッチ判定
├─ LaunchSystem      打ち上げと再点火
├─ GravitySystem     落下
├─ RiseSystem        せり上がり
├─ ScoreSystem       得点と連鎖
└─ RuleResolver      処理順の管理

Renderer             描画と演出
InputController      マウス／タッチ
PuzzleSolver         問題の探索と検証
```

描画中の座標ではなく、整数のマス座標でゲーム結果を計算します。  
同じ入力から必ず同じ結果になるようにし、リプレイとソルバーに利用できる設計にします。

## 17. 最初に検証すること

試作では、グラフィックより先に次を確認します。

1. マッチで塊が打ち上がる仕組みを直感的に理解できるか
2. 打ち上げ対象となる塊の範囲が分かりやすいか
3. 空中で横交換する操作が忙しすぎないか
4. 小さなマッチと大きな打ち上げの駆け引きが生まれるか
5. ブロックが落ちる方向と飛ぶ方向が混乱しないか
6. 偶然の連鎖だけでなく、狙って連鎖を作れるか
7. スマートフォンでも盤面とブロックが小さすぎないか

特に「重力は下、打ち上げは上」という二方向の動きが見づらい場合は、演出またはルールを単純化します。
