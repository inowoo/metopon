# METOPON（メトポン／仮）

**「一手を選ぶと、盤面が大きく動く」ターン制・打ち上げ連鎖パズル。**

『メテオス』の上方向へ飛ばす爽快感と、『パネルでポン』のブロック交換・せり上がる盤面を参考にしながら、忙しいリアルタイム操作をなくした独自ルールを目指します。

> このREADMEは、相談と試作を通じて更新していく企画・仕様書です。  
> まずブラウザ試作でコアルールを検証し、面白い部分だけを残していきます。

## 遊べる試作

**現在の基準バージョン：v0.7.0**

[index.html](./index.html) をブラウザで開くと遊べます。

### v0.7.0以降の重要な方針

- **2×2回転操作は使わない**
- **揃ったブロックを「点火待ち」にしない**
- 3個以上揃ったら、その場で自動的に点火・打ち上げへ進む
- プレイヤーが「発射」ボタンを押してタイミングを選ぶ仕組みは使わない
- 基本操作は、隣り合うブロックの交換に絞る
- 一手を選んだ後の打ち上げ・落下・連鎖は自動処理する
- 忙しいリアルタイム操作は要求しない

## 1. 企画概要

| 項目 | 内容 |
| --- | --- |
| 仮タイトル | METOPON（メトポン） |
| ジャンル | ターン制・打ち上げ連鎖パズル |
| 対応環境 | PC／スマートフォンのWebブラウザ |
| 操作 | マウス／タッチ |
| 基本人数 | 1人 |
| 時間制限 | なし |
| 盤面 | 6列 × 10行 |
| 通常ブロック | 4種類 |
| 中心となる遊び | 隣接交換 → 3マッチ → 打ち上げ → 落下 → 自動連鎖 |
| 現在のクリア目標 | 上端から合計30個を打ち上げる |
| せり上がり | 基本3手ごとに1段 |

## 2. ゲームの一言説明

盤面上の**隣り合う2個のブロックを交換**し、同じ種類を縦または横に3個以上そろえます。

マッチが成立したら、そこで操作を止める必要はありません。

**揃った瞬間に自動で点火し、打ち上げ、除去、落下、次の連鎖まで自動で進行します。**

盤面が安定したら、次の一手をゆっくり考えます。

## 3. 基本コンセプト

### 考える時間は止まっている

- 思考中は時間で盤面がせり上がらない
- プレイヤーは好きなだけ次の一手を考えられる
- 操作速度や反射神経を要求しない
- 一手を決めた後は結果を見守れる

### 一手で大きく盤面が動く

プレイヤーが行う主な操作は、ブロックの交換です。

その交換をきっかけに、

1. マッチ
2. 打ち上げ
3. 落下
4. 新しいマッチ
5. 連鎖

が自動で続きます。

「自分が選んだ一手から、予想以上に大きな結果が起きる」ことを気持ちよさの中心にします。

## 4. プレイヤー操作

### 基本操作

- 上下左右に隣り合う2個のブロックを選ぶ
- 2個を交換する
- 1回の交換で1手消費する
- マッチしない交換も可能
- 縦方向・横方向の両方を交換可能にする

マッチしない交換も許可し、数手かけて配置を仕込めるようにします。

### 採用しない操作

#### 2×2回転

以前の試作で検討した**2×2の4ブロック回転は廃止**します。

理由：

- 通常交換との役割が重なる
- 操作ルールが増えて分かりにくくなる
- 「どの操作を使うべきか」を考える負担が増える
- METOPONの中心を「交換から打ち上げる」遊びに絞りたい

#### 点火待ち／手動発射

以前の試作で検討した、

- 3個揃ったブロックを盤面に残す
- 「待」状態にする
- プレイヤーが好きなタイミングで発射ボタンを押す

という仕組みは**廃止**します。

3個以上揃った時点で即座に自動処理へ入ります。

## 5. マッチ

- 同じ種類を縦または横に3個以上そろえるとマッチ
- プレイヤーの交換後、盤面全体を判定する
- マッチしたブロックはすぐ点火する
- 4個以上のマッチは3個より強い打ち上げにする
- 十字、L字、複数ライン同時成立も強い結果になる
- 落下や打ち上げによって新しいマッチができた場合も自動で点火する

**マッチ成立後にプレイヤー入力は要求しません。**

## 6. 打ち上げ

METOPONの特徴は、揃ったブロックを単純に消すだけでなく、盤面を**上方向へ動かす力**として使うことです。

### 基本の流れ

1. 3個以上揃う
2. マッチしたブロックが点火する
3. マッチしたブロック自身が上方向へ飛ぶ演出を行う
4. マッチした位置の上にあるブロック列を押し上げる
5. 上端を越えたブロックを除去する
6. 残ったブロックが重力で落下する
7. 新しいマッチがあれば自動連鎖する

### 推力

現在の基準案：

| マッチ | 打ち上げ距離 |
| --- | ---: |
| 3個 | 2マス |
| 4個 | 4マス |
| 5個以上 | 6マス |
| 十字／L字 | 追加ボーナス |
| 複数ライン同時 | 各ラインの効果を合算 |

数値はプレイ感を見ながら調整します。

## 7. 自動連鎖

一度マッチが成立したら、盤面が安定するまで自動処理します。

### 自動処理

1. マッチ判定
2. 点火演出
3. 打ち上げ
4. 上端を越えたブロックを除去
5. 残ったブロックを落下
6. 新しいマッチを判定
7. マッチがあれば次の連鎖
8. マッチがなくなれば思考フェーズへ戻る

連鎖途中に、タイミング入力や追加ボタン操作は要求しません。

## 8. せり上がり

盤面はリアルタイムでは上昇しません。

- 基本は**3手ごと**に新しい1段を下から追加する
- 思考中に時間経過だけで追加されることはない
- 次のせり上がりまでの残り手数を表示する
- 自動連鎖中にはせり上がらない
- 大量打ち上げに成功すると、次のせり上がりを延期できる仕組みを残す
- すぐに揃えられる手がない場合は、盤面を動かすため自動で1段追加する案を試作する

## 9. ステージクリア

現在の試作基準では、

**上端から合計30個のブロックを打ち上げるとSTAGE CLEAR**

とします。

LAUNCH表示で、

`現在の打ち上げ数 / 30`

を確認できるようにします。

30個は固定仕様ではなく、プレイ時間と難易度を見て調整します。

## 10. ゲームオーバー

せり上がりが発生する時に最上段が塞がっており、新しい段を追加できない場合はGAME OVERです。

時間経過ではゲームオーバーになりません。

重要なのは、

**「次のせり上がりまでに盤面上部を空けられるか」**

です。

## 11. アシスト機能

現在の試作で使う候補：

- 一手戻し
- 早送り
- 最初からやり直す
- 自動保存／再開

**交換する2個そのものを答えとしておすすめ表示する機能は使いません。**

盤面を見て「どこを動かすか」を考えることをプレイヤーの判断として残します。

## 12. 手詰まり時

盤面にすぐ揃えられる交換が存在しない場合、何もできず止まるゲームにはしません。

現在の候補は、

**自動で下から1段追加して盤面を変化させる**

方式です。

これによって、

- プレイヤーに意味のない操作を要求しない
- ゲームの流れを止めない
- 盤面が少し危険になる

という効果を狙います。

## 13. ブロック

通常ブロックは4種類から開始します。

| 種類 | 表示 |
| --- | --- |
| 1 | 色＋丸 |
| 2 | 色＋三角 |
| 3 | 色＋四角 |
| 4 | 色＋星 |

色だけで判別させず、形と模様も併用します。

将来、基本ルールだけでは物足りないと判断した場合にのみ特殊ブロックを検討します。

## 14. 演出

METOPONでは盤面の動きを重要視します。

- 交換は実際にブロックが移動して見える
- マッチ時は発光やバーストを表示する
- 揃ったブロックは上方向へ飛び出す
- 上のブロックもピクセル単位で押し上げられる
- 落下も瞬間移動させず、実際に下へ動かす
- 新しい段も画面下から徐々にせり上げる
- 連鎖が起きた原因と結果を目で追える速度にする

通常速度では、端末の60Hz／120Hz表示に依存しない移動速度にします。

## 15. 一手の流れ

現在の基本フロー：

1. 盤面停止
2. プレイヤーが隣接する2ブロックを選ぶ
3. 交換
4. 1手消費
5. マッチ判定
6. マッチがあれば即点火
7. 打ち上げ
8. 上端を越えたブロックを除去
9. 落下
10. 新しいマッチがあれば自動連鎖
11. マッチがなくなるまで6〜10を繰り返す
12. 必要ならせり上がり
13. 盤面安定
14. 次の思考フェーズ

**途中に「点火待ち」や「発射待ち」は入りません。**

## 16. 面白さとして検証すること

現時点で最も重要なのは、機能を増やすことではなく、このコアルールが面白いかどうかです。

特に確認する項目：

1. 隣接交換だけでも十分に考える余地があるか
2. 一手から大きく盤面が動くことが気持ちいいか
3. 打ち上げ方向が分かりやすいか
4. 自動連鎖が「眺めているだけ」にならないか
5. 数手先を考えて仕込めるか
6. 偶然の連鎖と狙った連鎖のバランスが良いか
7. 3手ごとのせり上がりが適切か
8. 30個クリアが長すぎないか／短すぎないか
9. 手詰まり時の自動1段追加が面白さにつながるか
10. スマートフォンでも盤面と操作が分かりやすいか

## 17. 将来のパズルモード

コアルールが固まった後、固定盤面のパズルモードを追加します。

例：

- 指定手数以内に10個打ち上げる
- 1手で大量打ち上げする
- 指定回数の連鎖を起こす
- 上端付近の危険な盤面を立て直す
- 特定のブロックを上端から飛ばす

時間制限は設けません。

## 18. 問題生成とソルバー

将来的にはAIや自動生成器に盤面候補を作らせ、同じゲームルールを使うソルバーで検証します。

役割：

- AI／生成器：面白そうな問題候補を作る
- ソルバー：本当に解けるか検証する
- 人間：実際に遊んで面白いか判断する

ソルバーで、

- 解けるか
- 最短手数
- 解答数
- 意図しない簡単な別解
- 自動連鎖が終了するか

などを確認します。

## 20. 現在の決定事項

- 忙しいリアルタイム操作は入れない
- 考える時間に制限を設けない
- 基本操作は隣接ブロックの交換
- 交換する2個そのものを「おすすめ」として表示しない
- 上下左右への隣接交換を使う
- **2×2回転は使わない**
- **マッチ後の点火待ちは使わない**
- **発射ボタンでタイミングを選ばせない**
- 3個以上揃ったら自動で点火する
- 打ち上げ、落下、連鎖は自動処理する
- せり上がりは時間ではなく手数で進む
- 現在のクリア目標はLAUNCH 30個
- すぐ揃う手がない場合は、自動1段追加を試す
- ブラウザでマウス／タッチだけで遊べる
- 色だけでなく形でもブロックを区別する
- まずコアルールの面白さを優先して検証する
- 機能を増やしすぎず、不要な仕組みは削る

## 21. 今回廃止した仕様

v0.7.0の試作途中で次の要素を検討しましたが、今後の基本仕様から外します。

- 2×2のブロック回転
- 揃ったブロックの点火待ち
- 「待」状態
- 手動の発射ボタン
- 発射タイミングをプレイヤーが選ぶ仕組み
- 交換候補2個を答えとして強調表示する仕組み

理由は、操作や判断を増やすより、

**「交換を考える → 一手入れる → 一気に結果を見る」**

というMETOPONの核を明確にするためです。
